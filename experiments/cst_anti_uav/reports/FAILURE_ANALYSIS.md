# CST Anti-UAV — failure analysis (X1 on CST TEST)

Generated by `scripts/failure_analysis.py --x1` → `X1_failure_analysis.json`.
- Input: the frozen X1 TEST predictions (`runs/aerotrack_v3/x1_test_predictions/ste`) and the released GlobalTrack and SiamDT
  predictions.
- The per-sequence SA recomputed by the script equals the official toolkit's value for the released trackers; the script
  refuses to write otherwise.
- **Descriptive only.** No setting was changed after TEST access, and nothing here feeds back into any method.

## 1. Where the frames go

60 sequences, 72,175 frames: 59,250 with a visible target and 12,925 with the target absent.

| outcome | X1 STE | GlobalTrack | SiamDT |
|---|---:|---:|---:|
| visible: IoU ≥ 0.5 | **70.9 %** | 49.6 % | 49.9 % |
| visible: 0 < IoU < 0.5 | 6.1 % | 17.2 % | 17.1 % |
| visible: box with IoU 0 (wrong place) | 9.6 % | 33.2 % | 33.1 % |
| visible: no box (reported absent: a miss) | 13.5 % | 0 % | 0 % |
| absent: correctly reported absent | **71.0 %** | 0 % | 0 % |
| absent: false alarm (box on an absent target) | 29.0 % | 100 % | 100 % |

- X1's main visible-frame error is a **miss**: on 7,980 frames, 13.5 % of all visible frames, it reports "absent" while the
  target is there.
- The released trackers never miss in this sense because they always output a box. Their failure is the wrong box: a third of
  visible frames have IoU 0, which is drift or distractor lock.
- X1 converts most of that drift into either a correct box or an explicit "absent".

## 2. Is the gain only absence reporting? (absence-neutral SA)

Eq. 1 recomputed with **every absent frame scored 0 for every tracker**. This removes all credit for reporting absence and
puts X1 in the released trackers' situation. For the released trackers the value is unchanged, because they already score 0
there.

| | mSA (official) | absence-neutral mSA |
|---|---:|---:|
| X1 STE | 60.08 | **48.93** |
| GlobalTrack | 35.92 | 35.92 |
| SiamDT | 35.84 | 35.84 |

Absence-neutral, paired vs GlobalTrack over 60 sequences: **+13.00 SA, 95 % CI [+10.47, +15.52]**, 56 wins / 4 losses,
Wilcoxon p = 1.2e-10.

So about 11 of X1's 24-point margin comes from absence reporting, which the CST metric rewards by design (Eq. 1). The other
13 points come from better localisation on visible frames. This matches the visible-frame IoU decomposition in
`X1_test_official.md`: 56.67 vs 41.33, paired +14.88 [+11.93, +17.78].

## 6. Failure modes, ranked by the frames they cost

1. **Missed detections on tiny or low-contrast targets.** 13.5 % of visible frames, concentrated in building_* and urban-areas_*.
   The STE reports absence whenever no cached detection passes its frozen thresholds and motion gate (`det_thr` 0.15,
   `reacq_thr` 0.5, `gate_chi2` 25). This analysis does not separate a missing detection from a gated-out one. The
   thresholds were chosen on VAL and are not revisited on TEST.
2. **Distractor lock.** 9.6 % of visible frames have a box at IoU 0, and jungle_18 is the extreme case. The STE follows the
   strongest nearby detection. It has no appearance model, so once it is on a wrong drone-like blob it can stay
   there. This diagnosis is read from the per-frame outcomes; the distractors themselves were not inspected.
3. **False alarms while the target is absent.** 29 % of absent frames (3,745). Each one costs 1 SA-frame.
4. **Large targets.** Only 484 frames, but a clear gap vs template trackers, caused by a training-set size prior (6 large
   training frames).

What would plausibly fix each of these is listed as future work in `FINAL_REPORT.md`, and none of it was tried here:
- an appearance re-identification term in the STE for distractor lock;
- size-balanced augmentation for large targets;
- a VAL-tuned absence model.

Any such change needs a new registration and a new TEST pass, and is out of scope here.

## 7. X2: are X1's weak spots resolved? (seeds 1–2 and the single-frame control; descriptive)

Source: `scripts/failure_analysis.py --x2` → `X2_failure_analysis.json`. It reads the frozen predictions of the single X2 TEST
pass (PBS 93029) and X1's own pass. Its per-frame recomputation equals each pass's per-sequence SA, and the script refuses
otherwise. CIs are sequence bootstraps (B = 10000).

### Large targets (> 50 px): not resolved

| | large-target SA [95 % CI] | building_74 (159 frames) | cn_mountains_32 (188) | urban-areas_38 (89) | cn_sky_16 (34) |
|---|---|---:|---:|---:|---:|

| causal_g4 s1 | 27.08 [4.82, 76.83] | 51.2 | 6.5 | 0.0 | 83.5 |
| causal_g4 s2 | 25.97 [11.76, 73.17] | 36.8 | 13.1 | 7.8 | 79.4 |
| ttt s0 / s1 / s2 | 15.34 / 14.07 / 14.74 | 24.9 / 22.0 / 20.6 | 1.0 / 0.0 / 0.7 | 0.0 / 0.0 / 0.0 | 78.9 / 79.6 / 83.3 |
| GlobalTrack (released) | 34.52 [4.07, 62.39] | 61.0 | 0.0 | 45.1 | 66.3 |

- Every causal_g4 seed stays below GlobalTrack on large targets: 23–27 vs 34.5.
- The CIs are enormous because the 484 large frames come from only 8 sequences, 4 of them with ≥ 30 frames. No large-target
  claim in either direction is supported.
- The single-frame arm is worse still, 14–15.

**Cause and why it cannot be fixed within the protocol's evidence:**
- CST train contains **6** large-target frames, all in `urban-areas_4`.
- CST VAL contains 347, of which **337 are in a single sequence** (`building_47`).
- A large-target remedy (scale augmentation, size-balanced sampling) could therefore only be validated on effectively one VAL
  sequence. That is far too little power to select a change before a TEST pass, so no such change was trained (see
  `FINAL_REPORT.md` §6).

### `jungle_18` (880 frames, 367 target-absent): the visible-frame lock was seed-specific; absence errors remain

| | SA | visible: IoU ≥ 0.5 | visible: IoU 0 | absent: false alarm |
|---|---:|---:|---:|---:|
| X1 = causal_g4 s0 | 22.8 | 51.5 % | 48.3 % | 99.2 % |
| causal_g4 s1 | **44.6** | 88.5 % | 11.1 % | 92.4 % |
| causal_g4 s2 | **39.8** | 83.0 % | 16.8 % | 100 % |
| ttt s0 / s1 / s2 | 5.9 / 27.2 / 5.8 | 12.7 / 59.1 / 12.7 % | 87.3 / 40.9 / 87.3 % | 100 % |
| GlobalTrack (released) | 28.9 | 75.6 % | 7.6 % | 100 % (never reports absence) |

- X1's distractor lock on `jungle_18` is **not systematic**. The two other seeds of the same configuration track the visible
  target well and beat GlobalTrack on this sequence. So X1's only loss to GlobalTrack is partly seed variance.
- What remains for every seed is **absence**. 42 % of the sequence is target-absent, and all trackers (ours and released) put a
  box on 92–100 % of those frames.
- The single-frame arm locks onto the distractor far more often (87 % IoU-0 for seeds 0 and 2). This matches the window's effect
  in `ABLATION_RESULTS.md` §3.
