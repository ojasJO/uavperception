# Anti-UAV reproduction — anti-cheating / integrity audit

Performed 2026-09-19 on the new pipeline (`experiments/anti_uav/`) before any full training run, plus a
re-scan of the historical AeroTrack-Net code for the same patterns. Method: reading the actual data flow
(who reads labels, who reads the test split, what decides the reported number) — not only keyword search.
Where a static scan was used, its command and result are given so it can be re-run.

## A. New pipeline (`experiments/anti_uav/`)

| # | Pattern looked for | Finding | Verdict |
|---|---|---|---|
| A1 | hard-coded metrics | `reports/paper_reported_results.json` contains numbers — they are the **paper's** values, transcribed with table references, and only ever appear in the "Paper" column. No number in `src/` matches a metric-like literal (`grep -E "\b(6|7|8)[0-9]\.[0-9]{2}\b" src` → none). Our numbers exist only in generated `metrics.json` files. | legitimate / clean |
| A2 | hard-coded coordinates / trajectories | none. Boxes originate from label JSON (training, init frame) or model output (tracking). No plotting code exists yet; protocol §5 forbids typed coordinates. | clean |
| A3 | hard-coded frame numbers for favourable demos | none. The only frame numbers in code are the **four official start-frame corrections** (`data/antiuav.py::START_FRAME_CORRECTIONS`, from the dataset authors' README) — they define the tracker init frame, apply identically to every method, and are documented in the spec. | legitimate |
| A4 | test paths in training code | `engine/train.py` contains no `"test"` literal (smoke check 13 asserts it); data are loaded with `purpose='train'`/`'monitor'`, for which `load_sequences` refuses the test split; `validate_config` rejects `train_split`/`monitor_split == test`. | clean, enforced |
| A5 | test paths in hyper-parameter search | there is no hyper-parameter search. Phase B configs change one factor each and are evaluated on val; test remains final-only (`--final-eval`, ledger). | clean by design |
| A6 | random / manual checkpoint selection | none: the final-epoch checkpoint is the model (`last.pt == epoch_18.pt`), as GlobalTrack/the paper. The training-time monitor (`run_monitor`) is only printed and written to `metrics.jsonl`; grep shows no code path consuming `monitor_mSA_percent` except logging and a smoke assertion. Residual risk: a *human* could look at the monitor line and stop early; protocol §3 forbids it and `metrics.jsonl` would show it. | clean; human-side rule |
| A7 | manual result entry | `docs/ANTI_UAV_COMPARISON.md` is generated by `aggregate_results.py` from `metrics.json` files; header says "do not edit by hand". Reports (`report.md`) are generated from `metrics.json`. | clean |
| A8 | suspicious special cases (dataset / image / sequence-specific if-statements) | only `START_FRAME_CORRECTIONS` (see A3). No per-sequence, per-modality or per-image branch in model, sampler, tracker or metric code. | legitimate |
| A9 | model output overrides | tracker fallback: if the detector returns zero boxes, the previous box is repeated and counted (`n_fallback`, reported in `metrics.json` as `n_fallback_frames`). With `score_thresh=0` this should not occur; if it ever does, the count exposes it. The init frame's prediction is set to the GT init box — this is the challenge reference protocol (`out_res.append(init_rect)`) and identical for all methods. | legitimate, visible |
| A10 | fabricated visualisations | none exist. | n/a |
| A11 | evaluation reading ground truth during inference | `engine/track.py` reads GT exactly once per sequence: `seq.box_xywh(start)` for the init box (the SOT protocol). After that only frames are read. Metrics are computed later from saved prediction files (`eval/evaluate.py`), never inside the tracker. Smoke check 12 recomputes every SA independently from the files and verifies the metric reacts to perturbed predictions. | clean |
| A12 | ground truth used to modify predictions | none; predictions are written before any metric code runs. | clean |
| A13 | training accidentally loading test annotations | impossible via the public loader (A4). `verify_dataset.py` and `evaluate.py --final-eval` are the only callers that can open test labels; both are evaluation/verification tools. | clean, enforced |
| A14 | leakage between splits | `reports/dataset_verification.md`: 0 shared sequence names, 0 byte-identical label files or first frames across splits; test shares **no source video** with train/val; train and val share 26 videos **by the paper's own design** (documented, unchanged). | matches paper |
| A15 | silent preprocessing / split changes | none. Preprocessing is fixed in `_base_ir.yaml` and identical for both Phase A runs; splits are the official ones, frozen by manifest hash and verified at every evaluation. | clean |
| A16 | non-determinism | pair sampling / augmentation are a pure function of (seed, epoch, index) (smoke check 14); `cudnn.benchmark=True` (GlobalTrack default) leaves kernel-level non-determinism, recorded in `run_meta.json`. Single-seed Phase A is stated as such. | documented |

### Things that look suspicious but are legitimate (explained)

- **`res[start] = init_box` in the tracker** — the tracker "predicts" the ground-truth box on its init frame.
  This is the challenge reference behaviour and the SOT convention (the init box is an input, not a prediction);
  it affects all methods equally (≤ 1/T per sequence).
- **Pre-start frames scored as absent in the all-frames variant** — the tracker has no output before the init
  frame; the *primary* number excludes those frames entirely (spec §6), the variant is reported alongside.
- **`paper_reported_results.json`** — the paper's tables in machine-readable form, needed for the comparison;
  clearly labelled as the paper's numbers.
- **Batches forced to contain two different sequences** — DFSC's cross term is defined on different
  sequences; GlobalTrack's random sampler achieves this with probability 1 − 1/160 anyway (spec S5).

## C. Residual risks and how they are contained

1. **Single seed** — the paper's effect (+0.5 to +0.7 mSA) may be inside seed noise; Phase B seed runs are
   pre-planned and the comparison document says so before any number exists.
2. **Inferred settings** (single-GPU LR scaling, epoch definition, augmentation, β) — tagged in the spec;
   the sensitivity run `phase_b/dfsc_ir_lr0.02_accum8.yaml` probes the largest one.
3. **Human discipline** around the monitor line and the test ledger — the code makes misuse visible
   (`metrics.jsonl`, ledger), not impossible.
4. **Dirty working tree** — `run_meta.json` records `git.dirty` and the list of modified files; results
   produced from an uncommitted state are identifiable.
